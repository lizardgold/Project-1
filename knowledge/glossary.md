## Назначение

Документ содержит единый глоссарий терминов проекта "ПодписьОнлайн". Он используется при подготовке требований, OpenAPI-спецификаций, Sequence-диаграмм и других артефактов системного анализа.

Определения, основанные на описании продукта, приведены как исходные. Термины, точное техническое или юридическое значение которых требует уточнения, отмечены соответствующим образом.

## Термины продукта и бизнеса

| Термин                                                 | Определение                                                                                                                                      | Примечание                                                                |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| ПодписьОнлайн                                          | Сервис электронного подписания документов с телефона с использованием усиленной квалифицированной электронной подписи.                           | Название продукта                                                         |
| Клиент                                                 | Физическое лицо или индивидуальный предприниматель, использующий сервис для подписания документов.                                               | Пользователь продукта                                                     |
| Партнёр                                                | Банк, страховая организация или другая организация, интегрированная с сервисом и передающая документы на подпись.                                | Конкретный состав партнёров не определён                                  |
| Сотрудник партнёра                                     | Представитель партнёра, инициирующий передачу документа или пакета документов на подпись.                                                        | Пользователь продукта                                                     |
| Документ                                               | Документ, переданный в сервис для подписания и, при успешном завершении операции, хранения в подписанном виде.                                   | Форматы и ограничения не определены                                       |
| Пакет документов                                       | Группа документов, рассматриваемых в рамках одного сценария подписания.                                                                          | Правила атомарности и частичного подписания не определены                 |
| Подписание пакета документов                           | Функциональность, позволяющая клиенту подписать несколько документов в рамках одного пользовательского сценария.                                 | Фича проекта                                                              |
| Электронная подпись                                    | Электронные данные, связанные с подписываемой информацией и используемые для подтверждения подписания в соответствии с применимыми требованиями. | Конкретный механизм определяется техническими и юридическими требованиями |
| Усиленная квалифицированная электронная подпись (УКЭП) | Вид усиленной электронной подписи, соответствующий применимым требованиям к квалифицированной электронной подписи.                               | Конкретные требования к реализации и проверке необходимо уточнить         |
| Сертификат                                             | Сертификат ключа проверки электронной подписи, выпускаемый удостоверяющим центром в рамках предусмотренного процесса.                            | Термин используется в контексте сертификата электронной подписи           |
| Отзыв сертификата                                      | Процедура прекращения действия сертификата в соответствии с правилами удостоверяющего центра и применимыми требованиями.                         | Детали процедуры требуют уточнения                                        |
| Потеря телефона                                        | Ситуация, при которой клиент утратил устройство, использовавшееся для работы с сервисом, и требуется рассмотреть отзыв сертификата.              | Сам факт потери не определяет автоматически результат отзыва              |
| Подтверждение клиента                                  | Действие клиента, необходимое для подтверждения намерения подписать документ или пакет документов.                                               | Конкретный способ подтверждения не определён                              |
| Проверка подписи                                       | Проверка корректности электронной подписи подписанного документа.                                                                                | Проверяемые атрибуты и правила валидации требуют уточнения                |
| Подписанный документ                                   | Документ, для которого сформирована электронная подпись и результат подписания сохранён в соответствии с требованиями системы.                   | Точный критерий успешного завершения необходимо определить                |
| Операция                                               | Выполняемое системой бизнес-действие, например подписание пакета документов или отзыв сертификата.                                               | Состав атрибутов операции не определён                                    |

## Внешние системы и интеграции

| Термин                    | Определение                                                                                                    |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Удостоверяющий центр (УЦ) | Организация или система, участвующая в выпуске сертификатов и связанных с ними процедурах.                     |
| Госуслуги                 | Государственная цифровая платформа, упомянутая в контексте проекта.                                            |
| ЕСИА                      | Единая система идентификации и аутентификации.                                                                 |
| Система партнёра          | Информационная система банка, страховой организации или другого партнёра, взаимодействующая с «ПодписьОнлайн». |
| Интеграция                | Обмен запросами, ответами или другими данными между сервисом и внешней либо внутренней системой.               |

## Технические термины

|Термин|Определение|Примечание|
|---|---|---|
|API|Программный интерфейс взаимодействия между системами или компонентами.|Для внешних контрактов используется OpenAPI, если это принято в проекте|
|Endpoint|Адрес и путь API-операции, используемые для обращения к ресурсу или выполнения действия.|Конкретные endpoint'ы не определены|
|OpenAPI-спецификация|Машиночитаемое описание HTTP API, включающее операции, параметры, модели данных и ответы.|Формат и версия OpenAPI требуют согласования|
|Sequence-диаграмма|Диаграмма последовательности, показывающая взаимодействия участников во времени.|Используется для описания основных и альтернативных сценариев|
|Бизнес-правило|Подтверждённое условие, ограничение или требование, определяющее допустимое поведение системы.|Хранится в `business-rules.md`|
|Допущение|Предварительно принятое положение, которое не подтверждено исходными требованиями.|Хранится в `assumptions.md`|
|Открытый вопрос|Неопределённость, требующая ответа или решения заинтересованной стороны.|Хранится в `assumptions.md`|
|Тайм-аут|Ограничение времени ожидания ответа или завершения операции.|Конкретные значения не определены|
|Ретрай|Повторная попытка выполнения запроса или операции после ошибки либо отсутствия ожидаемого результата.|Условия повторения требуют согласования|
|Идемпотентность|Свойство операции, при котором повторное выполнение идентичного запроса в предусмотренных условиях не приводит к повторному бизнес-эффекту.|Наличие и механизм поддержки не определены|
|Статус|Значение, отражающее текущее состояние сущности или операции.|Полный перечень статусов не определён|
|Переход между статусами|Изменение состояния сущности в результате события или выполнения условия.|Допустимые переходы должны быть подтверждены требованиями|

## Правила использования терминологии
1. Использовать приведённые термины последовательно во всех аналитических артефактах.
2. Не считать синонимами сущности, различающиеся по бизнес-смыслу.
3. Не использовать термины «документ», «пакет документов» и «операция подписания» как взаимозаменяемые.
4. Не считать выпуск сертификата, его использование и отзыв одной операцией.
5. Не приписывать ЕСИА или Госуслугам конкретные функции в проекте без подтверждённого описания интеграции.
6. При появлении новых значимых терминов дополнять глоссарий.
